# Migration vers un seul Python 3.14 (design)

Date : 21/11/2026. Validé par Adrien le 21/11/2026. Branche : `env/python-3.14`.

## Intention

Ne plus jongler entre trois Pythons. Aujourd'hui :

- **3.8 (Anaconda)** : référence officielle (README, CI GitHub, versions figées des `requirements-*.txt`, règle « Python 3.8 » des briefs) ;
- **3.9.9 (`../syride_traces_py39`, python.org)** : environnement utilisé au quotidien, notamment pour le scraping ;
- **3.12 (Homebrew)** : inutilisé par le projet.

Cible : **Python 3.14 partout** (Mac et CI), un seul environnement, une seule source de vérité pour les dépendances.

## Objectifs

- Un environnement unique `.venv/` (Python 3.14) à la racine du dépôt, géré par uv.
- Dépendances déclarées dans `pyproject.toml`, figées dans `uv.lock`.
- Code compatible pandas 3 et numpy 2, **sans changement des statistiques publiées**.
- Scraping fonctionnel sous 3.14.
- CI, README, Makefile et briefs alignés sur 3.14.

## Non-objectifs

- Réparer le rapport PDF (`report_functions.py`, déjà cassé) : ses dépendances restent installables, rien de plus.
- Moderniser le code au-delà de ce qu'exige la migration (pas de réécriture en syntaxe 3.10+ pour le plaisir).
- Toucher au front (`web/`), hormis la mention de Python dans les briefs.

## Anti-objectifs (échec même si « ça marche »)

- Une statistique publiée qui change sans explication.
- Des données réelles (pkl, base, export) commitées.
- Un ancien Python supprimé sans l'accord explicite d'Adrien.

## Contraintes

- Mac Intel (x86_64), macOS 26 ; uv 0.13.7 déjà installé (`~/.local/bin/uv`). Résolution à blanc vérifiée le 21/11/2026 : toutes les dépendances ont des wheels 3.14 x86_64 (pandas 3.1.1, numpy 2.5.5, geopandas 1.2.0, matplotlib 3.11.2, plotly 7.1.0, selenium 4.53.0, fastkml 1.4.0).
- `.gitignore` fonctionne en liste blanche : `pyproject.toml`, `uv.lock` et `.python-version` doivent y être ré-autorisés ; `.venv/` reste ignoré.
- `undetected-chromedriver` 3.5.5 importe `distutils` (retiré en 3.12) : ajouter `setuptools` au groupe scraping.
- `global_flights_data.pkl` est régénéré depuis `flights.db` (`main.py --pkl`), donc l'incompatibilité éventuelle des pickles pandas 1.5 → 3 se règle par régénération.
- Scraping réel : protégé par Turnstile, se lance avec Adrien.

## Approches envisagées

1. **uv (retenue)** : déjà installé, télécharge lui-même Python 3.14, gère environnement et verrouillage, s'intègre en CI (`astral-sh/setup-uv`).
2. Conda/Anaconda : c'est un des Pythons qu'on veut retirer.
3. Installateur python.org + pip + requirements : une installation système de plus, pas de verrouillage.
4. pyenv : un outil de plus pour ce que uv fait déjà.

## Design

- **Python** : `uv python install 3.14` ; `.python-version` = `3.14`.
- **`pyproject.toml`** (projet non packagé, `[tool.uv] package = false`), `requires-python = ">=3.14"` :
  - dépendances de base : export, tests, expected_stats, publish (pandas, numpy, jsonschema, python-dotenv, plotly, beautifulsoup4) ;
  - groupes : `dev` (pytest), `scraping` (fastkml, selenium, undetected-chromedriver, setuptools), `pdf` (matplotlib, seaborn, fpdf2, kaleido), `notebooks` (notebook, geopandas, simplekml, etc., d'après les imports réels).
  - `uv sync --all-groups` installe tout sur le Mac ; la CI installe base + dev (+ scraping si les tests en ont besoin).
- **Suppression** de `src/requirements-*.txt`.
- **Makefile** : `PYTHON ?= uv run python` ; nouvelle cible `env` (`uv sync --all-groups`).
- **Garde-fou statistiques** :
  1. avant toute modification, export de référence avec l'ancien Python (3.9 ou 3.8) sur les données réelles, copié hors dépôt ;
  2. après migration, ré-export sous 3.14 et comparaison JSON fichier par fichier (hors hash et horodatages) ;
  3. `make test-py` et `make expected-stats` verts ; toute différence est expliquée ou corrigée.
- **pandas 3** : traiter Copy-on-Write (affectations chaînées), dtype chaîne par défaut, dépréciations de numpy 2 ; corrections minimales et ciblées.
- **CI** : job Python sur `ubuntu-latest`, `astral-sh/setup-uv`, Python 3.14, `uv sync --locked`, même commande pytest.
- **Documentation** : README (installation via uv), `src/README.md`, `src/MIGRATION_SCRAPING.md` si concerné, règle « Python 3.8 » remplacée par « Python 3.14 » dans `web/BRIEF_PHASE8_METEO.md` (seul brief actif ; les archives restent telles quelles).
- **Recette scraping** avec Adrien : un lancement court réel sous 3.14.
- **Ménage final**, chaque suppression confirmée par Adrien : `../syride_traces_py39`, Python 3.9 de python.org, Anaconda (après vérification qu'aucun autre projet ne l'utilise).

- Les bornes de versions dans `pyproject.toml` (le verrou fait foi).
- Le détail des corrections pandas 3, tant que le garde-fou passe.
