# Migration vers un seul Python 3.14 : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remplacer les trois Pythons du projet (Anaconda 3.8, venv 3.9, Homebrew 3.12) par un seul environnement uv en Python 3.14, sans changer aucune statistique publiée.

**Architecture:** uv installe Python 3.14 et crée `.venv/` à la racine ; `pyproject.toml` déclare les dépendances (base + groupes), `uv.lock` les fige ; tout se lance par `uv run` (Makefile, npm, CI). Un garde-fou compare pkl et export produits par l'ancien et le nouvel environnement sur une copie des données réelles.

**Tech Stack:** uv 0.13.7, Python 3.14, pandas 3.x, numpy 2.x, pytest, GitHub Actions (`astral-sh/setup-uv`).

**Spec:** `docs/superpowers/specs/2026-11-21-python-3.14-design.md`

## Global Constraints

- Python : `3.14` partout (`.python-version`, `requires-python = ">=3.14"`, CI).
- Outil unique : uv (`~/.local/bin/uv`). Pas de conda, pas de pip direct, pas de pyenv.
- Environnement : `.venv/` à la racine du dépôt, jamais commité.
- `.gitignore` est en liste blanche : ré-autoriser `/pyproject.toml`, `/uv.lock`, `/.python-version`.
- Données réelles (pilotes, `flights.db`, pkl, `web/public/data/`, copies de recette) : jamais dans le dépôt. Recette dans `/Users/Adrien/Documents/paramoteur/syride/analyze_traces/recette_py314/` (hors dépôt).
- Aucune statistique publiée ne change ; toute différence d'export est expliquée et validée par Adrien ou corrigée.
- Corrections pandas 3 / numpy 2 minimales et ciblées ; pas de modernisation gratuite du code.
- Rapport PDF (`report_functions.py`) : installable, non réparé.
- Scraping réel : uniquement avec Adrien (Turnstile, quota quotidien Syride).
- Aucune suppression d'ancien Python sans accord explicite d'Adrien, une suppression à la fois.
- Commits sur `env/python-3.14` ; ne pas pousser sans accord d'Adrien.

## Review Focus

1. **Ancien pkl lu par pandas 3** : `make publish` ou `main.py --pkl 0 --publish 1` réutilisent le pkl existant, écrit par pandas 1.5. Attendu : il se charge sous 3.14, ou un message clair demande de le régénérer (test en tâche 4).
2. **`python` du shell = Anaconda 3.8** : toute commande documentée ou lancée en sous-processus doit passer par `uv run` ou `sys.executable`, jamais par un `python` nu (vérifié en tâche 3 et tâche 6).
3. **dtype chaîne de pandas 3** : `None`/`NaN` dans les colonnes texte et tests `dtype == object` peuvent changer le JSON exporté (`null` vs absent, `"nan"`). Attendu : JSON identique (tâche 4).
4. **`undetected-chromedriver` et `distutils`** : l'import doit réussir sous 3.14 (tâche 2), et un vrai lancement doit ouvrir Chrome (tâche 7).
5. **Notebooks** : `uv run jupyter notebook` doit ouvrir `src/analyze_traces.ipynb` avec le noyau de `.venv` (tâche 2).
